# Figma MCP — правка и сборка в Figma

Раздел про работу с Figma через `use_figma` (Plugin API). Перед любым вызовом обязательно грузить скилл `figma-use` (через `get_figma_skill` по `skill://figma/figma-use/SKILL.md`), для компонентов — дополнительно `figma-generate-library`.

- **`get_variable_defs` и design-context отдают то, что использует НОДА, а не то, что есть в библиотеке.** Это главный источник ложных выводов: спросил переменные у ноды героя, получил семь штук, решил «в Figma больше ничего нет» — и трижды за сессию заявил пользователю, что переменной не существует, когда она существовала (`Spacing XL`, `Text/Inverted`, десктопный `Birch/Paragraph LG`). **Из «нода этим не пользуется» не следует «этого нет».** Чтобы узнать, что в библиотеке есть на самом деле:
  - **перечислить** — `search_design_system` с `includeVariables: true` / `includeStyles: true`. Запрос ищет по имени подстрокой, поэтому спрашивать надо словом из семейства (`Spacing`, `Paragraph`, `Button`), а не описанием задачи: запрос «display heading text style» вернул пустой список при семи существующих стилях абзаца.
  - **получить значения** — `search_design_system` отдаёт только имена и ключи. Значения читаются через `use_figma` → `importStyleByKeyAsync(key)` (для стилей) и дают `fontSize`, `lineHeight`, `letterSpacing`, `fontName`. Для переменных — `importVariableByKeyAsync`.
  Порядок всегда такой: сначала перечислить библиотеку, потом читать значения, и только потом говорить «такого нет».

- **Инстансы в макете бывают ручного ресайза — сверять сходимость чисел.** Design-context отдаёт числа инстанса, а не компонента, и если фрейм тянули за угол, они перестают быть правдой. Признак — арифметика не сходится: у кнопки в мобильном фрейме `padding-top: 27` + `text: 18` + `padding-bottom: 33` = 78 при заявленной высоте `60`. Я взял оттуда кегль 18, а в компоненте он 24. **Перед тем как брать размер из инстанса, проверить, что паддинги плюс контент дают заявленный размер.** Не сходится — искать значение в компоненте или спрашивать дизайнера.

- **Клон вместо создания — обход шрифтового блокера.** `node.clone()` переносит текст вместе с брендовым шрифтом и **не требует его загрузки**, потому что ничего не мутирует. Поэтому любой узел с TT Commons (локап, таб, готовая подпись) нужно не пересобирать текстом, а клонировать из существующего и дальше работать с копией. Тем же упирается `instance.setProperties()` на текстовое свойство — падает с «Unable to update this text property because the component uses a font that isn't available»; вместо этого клонировать инстанс, у которого нужное значение уже проставлено дизайнером.
- **`rescale()` обходит шрифтовой блокер — это способ сделать масштабный вариант лока́па.** `node.rescale(k)` **не требует загрузки шрифта**: он пропорционально пересчитывает `fontSize`, паддинги, радиусы, `strokeWeight` и все вложенные узлы, включая текст на недоступном брендовом шрифте. Поэтому мобильную версию блока собирать так: клонировать десктопные узлы → `rescale(мобильный кегль / десктопный кегль)` → перегруппировать в новые ряды. Геометрия сходится точно (проверено: «for» 64px × 30/52 → 36.92, «Ad automation» 388 → 223.85, паддинг 24 → 13.85, радиус 16 → 9.23, кегль 52 → 30). Прямая запись (`node.fontSize = …`, `setTextStyleIdAsync(...)`) в тех же условиях падает с «Cannot write to node with unloaded font». Реальный кейс — мобильный фрейм `hero / mobile 320`.

- **Атомарность `use_figma` не работает, если ошибку поймать самому.** Скрипт откатывается целиком только когда исключение **вылетает наружу**. Если обернуть запись в `try/catch`, частично применённая мутация останется в файле. Реальный кейс: `setTextStyleIdAsync()` под `try` успел выставить `fontSize: 32` и упал на следующем шаге — узел остался с чужим кеглем, а скрипт отчитался «ok: false». Вывод: пробы, которые что-то пишут, делать **без** `catch` (пусть падают и откатываются), либо сразу после `catch` восстанавливать значение — и обязательно перечитывать состояние, а не верить возвращённому статусу.

- **Шрифтовой блокер — главное ограничение.** `use_figma` исполняется в **серверном окружении** с набором Google Fonts. Брендовые шрифты (`TT Commons Pro Variable`) там **недоступны**, а Figma не даёт менять текст в ноде, пока не загружен её текущий шрифт → **править тексты в брендовых слоях через MCP нельзя**. Подменять шрифт на доступный — нельзя, это переклинит дизайн. Рабочий обход: создать **рядом параллельный reference-блок на Inter** с теми же текстами, пользователь копирует вручную. Проверять доступность через `figma.listAvailableFontsAsync()`.
- **Точечная правка текста вместо перезаписи.** Присвоение `node.characters` **сбрасывает смешанные стили** (жирные метки, цветные диапазоны) — всё становится стилем первого символа. Для замены фрагмента использовать `deleteCharacters(i, i+len)` + `insertCharacters(i, newStr, 'BEFORE')` — окружающие стили сохраняются.
- **Exposed nested instance — во всех вариантах сета.** Чтобы свойство вложенного инстанса всплыло на верхний уровень, `instance.isExposedInstance = true`. В **component set это надо сделать в каждом варианте**, иначе при переключении состояния (Idle/Hover/Active) переключатель пропадёт. Оговорка: при смене родительского варианта значение вложенного свойства может сбрасываться на дефолт — если критично, делать свойство на самом родителе или INSTANCE_SWAP.
- **Node ID протухают — проверять якорь перед записью.** ID из предыдущих вызовов могут перестать резолвиться (сменился файл/ветка/страница, пользователь пересобрал структуру). Перед записью проверять `getNodeByIdAsync` на якорный узел и, если `null`, — переоткрывать структуру по имени страницы/слоя, а не гадать по старым id.
- **SVG и компоненты.** `figma.createNodeFromSvg(svg)` вставляет SVG настоящим вектором. `figma.createComponentFromNode(node)` превращает узел в компонент. После `combineAsVariants` варианты **стакаются в (0,0)** — обязательно раскладывать (проще всего дать сету auto-layout).

### Правила сборки макетов в Figma

Три обязательных требования при любой сборке layout'а через `use_figma` — макет отдаётся дизайнеру на доработку, и всё перечисленное иначе ломает эту доработку:

- **Отступы и радиусы — только на переменных.** Импортировать из коллекции «Birch / bir.ch» через `importVariableByKeyAsync`, привязывать через `setBoundVariable('paddingTop' | 'itemSpacing' | 'topLeftRadius' | …, v)`. Литерал допустим, только если токена с таким значением не существует — и о таких местах сообщать явно списком, а не молча оставлять. Если значение почти совпадает с существующим токеном, использовать токен: например, у пилюли любой радиус больше половины высоты рендерится одинаково, поэтому `Radius 24` заменяет магические 23 и 10.5 без визуальной разницы.
- **Высота auto-layout приходит от контента** — вертикальные контейнеры остаются `HUG`. Фикс-высота только там, где её требует форма (кружок, квадратная кнопка), а не там, где «так получилось на макете».
- **Служебные фреймы без заливки.** `figma.createAutoLayout()` создаёт фрейм с **белой заливкой по умолчанию**. На всех структурных контейнерах (`card-head`, `badges`, ряды маркеров) обязательно `fills = []` — иначе при смене фона карточки вылезают белые прямоугольники-призраки. Заливку оставлять только тем поверхностям, которые реально покрашены в дизайне.
- **`clipsContent` не вешать автоматически.** Auto-layout-фреймы приезжают с включённым Clip content, и на служебных контейнерах его надо снимать (`clipsContent = false`). Иначе дизайнер не может вынести за край ни бейдж, ни декор, ни тень, а обрезка происходит молча — на канвасе просто «пропадает» кусок элемента. Оставлять включённым только там, где обрезка — часть формы (кружок с буквой внутри).

После сборки — пройтись по дереву и проверить три вещи: заливки служебных фреймов, вертикальный sizing, наличие `boundVariables` на отступах. Отчёт о том, что осталось литералами, отдавать вместе с результатом.

- **Повёрнутые объекты: метаданным не верить, брать `get_design_context`** — `get_metadata` отдаёт для повёрнутых слоёв bounding box, и для двух из трёх карточек в группе `02_4` он оказался сдвинут на 200+ единиц вправо (cherry 1048.94 при реальных 810, jar 1045.87 при 957); дизайн-контекст той же группы отдаёт верные `left/top`, настоящие размеры до поворота и сам угол (`rotate-[…deg]`), а живой скриншот группы подтверждает именно его. Реальный кейс 02.09.2026: две карточки коллажа стояли за краем холста, пока геометрия бралась из метаданных. Для неповёрнутых слоёв метаданные и дизайн-контекст совпадают.
- **Вложенные дети фрейма: координаты относительные, не абсолютные** — инстансы внутри фрейма (`Frame 2611104` → три Rule card) приходят с координатами от родителя, хотя выглядят как абсолютные. Проверять по экспорту родителя: в `rules.png` Pause начинается на x≈91 / y≈62 внутри 276×275, что совпало с «сырыми» числами метаданных, а не с вычитанием позиции рамки.
