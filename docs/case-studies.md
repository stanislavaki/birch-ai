# Кейсы (case studies) в Webflow CMS

Кейс — это **запись в CMS-коллекции**, а не отдельная страница. Шаблон один, общий на все
кейсы: `bir.ch/case-studies/<slug>`. Любая правка шаблона или его классов меняет сразу все кейсы.

## Как залить новый кейс

1. **Посмотреть ассеты глазами до заливки.** Логотип обязательно отрендерить на белом и прочитать
   по буквам: у Empros клиентский файл пришёл с опечаткой (`EMRPOS`). Глифы в растре не править —
   брать корректный логотип у клиента или из шапки его сайта; перекраска (белый → чёрный) допустима
   с согласия пользователя.
2. **Картинки.** Фото (`main`, галерея, фото в теле) → WebP q82; OG → JPEG 1200×630 (пережать, если
   тяжелее ~150 КБ); логотипы 2–10 КБ не трогать. Имена: `<slug>-main.webp`, `<slug>-logo.*`,
   `<slug>-gallery-N.webp`, `<slug>-og-1200.jpeg`. Загрузка — `create_asset` + POST на S3
   (`docs/webflow-mcp.md`, «Ассеты и картинки в CMS»). Webflow всё равно перезальёт файл под новым
   id — дубль в Asset manager неизбежен, сирот не удалять без аудита.
3. **Поля записи.**
   - `name` = H1, sentence case, `Bïrch` через ï; `slug` короткий, после публикации не менять.
   - `meta-title`: `<Company> | Case Study | Birch (Revealbot)`; `meta-description` — от третьего
     лица про результат клиента, с названием компании (правило в `CLAUDE.md`).
   - Метрики 0–4 (`metric-N-value` / `-label`), `metric-color` не заполняем.
   - Карточка компании: `company-description`, `website` + `website-label`, `location`,
     `business-type`, `user-since` («since 2026»), свитчи платформ.
   - Цитата: `quote-1-text` **без кавычек** (шаблон ставит свои), `quote-1-author`, `quote-1-title`;
     аватар необязателен — пустой скрывается.
   - `blue` / `pink` — фон и обводка карточки в списке при ховере (и тон плашек метрик); брать
     готовую пару из палитры существующих кейсов, не изобретать.
   - `gallery` — картинки «в конце» кейса; `opengraph`; `video` (YouTube) — пустое скрывается само.
4. **Тело (`case-body`, рич-текст).** `h2` Challenge / Solution / Results → `h3` (Title Case) → `p`.
   Без `<strong>` в заголовках, типографские апострофы и тире. Спец-блоки — ниже.
5. **Публикация.** Сначала только стейджинг: `publish_site` с `publishToWebflowSubdomain: true` и
   пустым `customDomains`. Публикация асинхронная — опрашивать реальный URL с `?cb=<random>` (обход
   ~15-минутного кэша) до 200. Запись с `isDraft: false` уедет на прод с ближайшей полной публикацией
   `bir.ch`; прод — только по явной команде пользователя.

## Спец-блоки внутри `case-body`

Все три работают как **прогрессивное улучшение**: в CMS лежит обычная разметка, скрипт шаблона на
опубликованной странице собирает из неё блок. В Designer/Preview скрипты не выполняются — там видна
исходная разметка, это ожидаемо.

- **Картинка в теле** — нативная фигура Webflow, байт-в-байт:
  `<figure class="w-richtext-figure-type-image w-richtext-align-fullwidth" style="max-width:<W>px" data-rt-type="image" data-rt-align="fullwidth" data-rt-max-width="<W>px"><div><img alt="__wf_reserved_inherit" src="<URL>" width="auto" height="auto" loading="lazy"></div></figure>`,
  где `<W>` — реальная ширина файла в px. Подпись — `<figcaption>` внутри.
- **Карточка стратегии** — маркер из трёх элементов подряд: фигура с иконкой (Pause / Duplicate /
  Scale `.svg`, URL брать из тела существующего кейса), `<p><a href="https://app.bir.ch/share/…">Заголовок</a></p>`,
  `<p>Описание</p>`. Заголовок и описание читать со share-страницы в браузере (curl отдаёт только og:title).
- **Pro-tip** — `<h4>Pro-tip: Заголовок</h4>` + абзацы/списки под ним. Скрипт оборачивает их в
  `.cs-protip` (светло-серый токен, радиус 1rem, паддинг 1.25rem — как у карточки стратегии), префикс
  превращает в подпись нативным классом `.eyebrow` («PRO TIP», отступ под ней 0.25rem). Текст совета — на ступень мельче тела: токены Paragraph SM (0.875rem / 1.3). Фон плашки — цвет кейса: скрипт берёт его с плашек метрик (поле `blue`, инлайн-стиль); у кейса без метрик остаётся светло-серый токен. `h4` в кейсах зарезервирован под
  pro-tip. Блок заканчивается на первом элементе, который не `p`/`ul`/`ol`.
- **Дополнительная цитата** — `<blockquote>“…”</blockquote>` (стиль как у верхней цитаты).

## Кастом-код шаблона

Каноника — в репозитории: [`webflow/case-study-template.head.html`](../webflow/case-study-template.head.html)
и [`webflow/case-study-template.footer.html`](../webflow/case-study-template.footer.html). Это
побайтная копия freeform-блоков страницы шаблона. Порядок правки: `get_page_freeform_code` → сверить
с файлом → править файл → `set_page_freeform_code` целиком → опубликовать стейджинг → вытащить блоки
из HTML страницы и сравнить с файлом (у записи через API `\uXXXX` в JSON раскрывается в литерал —
после сверки привести файл к живому виду).

Грабли, найденные на кейсах:
- Глобальное правило тега `h4 { max-width: 400px }` ломает заголовки в теле на две строки — в head
  шаблона снято через `.cs-rich h4 { max-width: none }`.
- Отступ цитата → тело живёт в классе `.cs-quoteblock` (margin-bottom + padding-bottom токенами):
  3rem на десктопе, 2rem на ≤767.
- Шапка на ≤991 (колонки в стопку): картинка → логотип → заголовок → метрики → тело идут с единым
  шагом 2rem. Держится на `.cs-full-tblock` margin-top (medium) и `.cs-full-cols` margin-bottom
  (medium + small) токеном 2rem. Нижний margin H1 (20px от глобального правила тега) на ≤991 обнулён
  комбо-классом `.h1-54.cs-hero-title` — только на шаблоне, общий `.h1-54` не тронут; десктоп без изменений.
- Логотип в шапке (`.cs-full-logo`) вписывается в рамку **9rem × 2.5rem** на всех ширинах:
  `width: 9rem; height: auto; max-height: 2.5rem; max-width: 100%; object-fit: contain;
  object-position: 0% 50%`. Компактные логотипы упираются в высоту, длинные — в ширину, так что
  визуальный вес выравнивается (раньше была только `max-height: 2rem`: Keiki 88×35 против Empros
  354×35). Почему `width` + `height: auto`, а не пара `max-*`: `max-*` только ограничивает, и SVG с
  собственным размером 36px не увеличивался. Бокс элемента всегда 9rem шириной — у компактных
  справа невидимый запас, слева всё прижато к заголовку.
  **Нарезка:** фрейм 36px в высоту, экспорт SVG или PNG 4×; фрейм вплотную по знаку (поля по бокам
  теперь уменьшают логотип), версия в одну строку без слогана, тёмный знак на прозрачном фоне,
  в SVG нет вшитого растра, название прочитать по буквам. PNG 2× (72px) на ретине замыливаются.
- В скрытой панели `loading="lazy"`-картинки не грузятся и меряются как 0×0 — перед замером ставить
  `loading = 'eager'` и переприсваивать `src`.
- Панель браузера в фоне отдаёт пустые скриншоты и `innerWidth: 0` — проверять замерами через JS с
  явно заданным вьюпортом, а не картинкой.
