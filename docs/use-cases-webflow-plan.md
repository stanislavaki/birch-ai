# Перенос `use-cases.html` в Webflow — план (вариант B: гибрид «нативные блоки + custom-код»)

## Контекст
`use-cases.html` — dev-страница «Learn the difference» (AI / MCP / Meta MCP): hero + 3
продуктовые карточки → фильтр-табы → двухколоночный layout (sticky sidebar-аккордеон
«Workflows» + контент из 6 workflow-секций с ~18 карточками кейсов). Плюс мобильный слой:
H2-разделитель, видимый фильтр 2×2, чёрный плавающий бар «Workflows», выезжающая панель
с жёлтой обводкой (стиль курсового меню bir.ch). Вся интерактивность — один DOM-driven
IIFE (TOC строится из контента, фильтр по `data-*`, scroll-spy, мобильный sheet с
reparenting'ом).

Embed'а у страницы **нет** — это первый перенос. Размер ~80 КБ (> лимита одного Webflow
Embed ~50k), поэтому «один большой embed» не подходит.

Выбран **вариант B — гибрид**: контент и структура — родными Webflow-элементами
(редактируются в Designer), базовые стили — нативно в панели на Webflow-переменных,
эффекты/состояния/мобилка — в custom `<style>`, логика — в page custom code.

## Принцип разделения стилей
- **Панель Webflow (нативно, на Webflow-переменных)** — бокс-модель, типографика,
  раскладка, размеры: паддинги, радиусы, фоны, шрифты, flex/grid, gap, `position: sticky`.
- **Custom `<style>` (Page → Inside `<head>`)** — только то, что панель не умеет.

### Что остаётся в custom `<style>` (по факту grep'а страницы)
- `mask-image` (×5): seal-бейдж цитаты `.uc-banner__mark::before`, иконка copy `.uc-copy::after`.
- `color-mix()` (×2): тон кнопки copy + hover.
- псевдоэлементы `::before/::after` (×5): точка активного пункта TOC, seal, иконка copy.
- аккордеон-анимация `grid-template-rows: 0fr → 1fr` (×5).
- секционные цвета `--wf-c/--wf-cd` (×17): 6 модификаторов `.uc-wf--audit…` задают
  переменные, потребители (seal-fill, copy-тон, hover TOC) — тут же.
- `outline` + `outline-offset` — пунктирная рамка roadmap-карточки (в панели только border).
- `clamp()` заголовка баннера (или размеры по брейкпоинтам в панели).
- состояния по JS-классам: `.is-on`, `.is-open`, `.is-active`, `.is-hidden`, `.is-visible`.
- **мобильный медиазапрос** (fixed FAB-бар, sheet, жёлтая обводка, H2-разделитель, воздух
  баннера) — в custom. **Кроме** самой раскладки таба 2×2 — она на глобальном классе
  `.filter-tabs` (см. раздел «Переиспользуемые табы»).
- `text-wrap: balance/pretty` — нативно, если в Designer есть контрол Typography → Text
  Wrap; иначе одной строкой в custom.

**Subgrid, `:has`, backdrop-filter, aspect-ratio — на странице НЕ используются.**

### `:root{}`
В гибриде большой копии `tokens.css` **не нужно**: примитивы берут Webflow-переменные из
панели. Мини-`:root{}` заводим только под токены, на которые ссылаются оставшиеся
custom-правила (часть значений можно просто захардкодить в `<style>`).

## Стратегия классов (важно)
- Где есть готовый **класс дизайн-системы** — переиспользовать его (не плодить свой);
  после каждого назначения через MCP сразу `query_elements` и **сверять `styleNames`** —
  если затащило combo-цепочку, откат и назначить класс в Designer.
- Свой класс (`uc-banner`, `uc-toc`, `uc-card`…) — только там, где DS-эквивалента нет.
- «Уникальность» — не самоцель, а следствие: новый класс резолвится чисто. Настоящая
  защита — сверка `styleNames`, а не «никогда не переиспользовать».

## Переиспользуемые табы (отдельный слой)
Табы нужны на других Webflow-страницах. Сейчас скоуп — **визуал (десктоп + мобилка)**;
логика — позже.
- **Визуал — нативный глобальный класс Webflow** `.filter-tab` / `.filter-tabs` (+ combo
  `.filter-tab.is-on`), стилизованный в панели **по брейкпоинтам**: на десктопном —
  сегмент-ряд (флекс, паддинги/размеры), на мобильном (≤767) — сетка 2×2
  (`grid-template-columns: repeat(2, 1fr)`, тач-высота таба). Оба состояния лежат на
  глобальном классе → едут на все страницы, правятся в одном месте. **Custom code для вида
  не нужен.** Опционально сверху обернуть в **Component** (Designer) для drag-drop реюза;
  инстансы рендерятся в обычный DOM.
- В page-custom остаётся только **роль таба на странице use-cases**: что на мобилке
  `.uc-tabs-wrap` остаётся видимым (не прячется), H2-разделитель над ним, позиция в потоке.
- Примечание: 2×2 рассчитан на 4 таба; `repeat(2, 1fr)` при другом числе просто переносит
  на новые ряды — если нужен универсальный дефолт, рассмотреть `auto-fit`/`flex-wrap`.
- **Логика — позже**, отдельно: generic site-wide скрипт на data-контракте
  (`data-filter-group` / `data-filter` / `data-filter-tags`), диспатчит событие
  `filter:change`; страничная часть use-cases (каунты, лейбл, TOC) слушает его.
  Нейминг увести от use-cases: `uc-tabs`→`filter-tabs`, `data-products`→`data-filter-tags`.
- Фильтрация остаётся **клиентской** (весь контент на странице, JS прячет по тегам) — самый
  портируемый вариант.

## Фазы

### Фаза 0 — подготовка (один синхронный заход)
1. Создать/выбрать страницу в Webflow. site_id bir.ch = `6716718ea408f53194adf9a9`.
   Один раз вызвать `webflow_guide_tool`.
2. Шрифты на сайте: **PP Pangaia** (serif-цитаты, вместо dev-стенда Fraunces) +
   **JetBrains Mono** (промпты).
3. Ассеты → `asset_tool`, забрать asset id: 3 локапа (`birch-ai/birch-mcp/meta-mcp.svg`),
   `seal.svg`, `copy-icon-outline.svg`. (Плюс/крестик — инлайн-SVG.)
4. Сверить, какие **Webflow-переменные** уже есть под наши токены (цвета, `_sizes---*`,
   радиусы) — на них стилим примитивы; чего нет — литерал или завести переменную.

### Фаза 1 — примитивы нативно (Webflow MCP + панель)
Собрать элементы `data_element_builder`'ом, базу стилить через `data_style_tool`/панель на
Webflow-переменных: карточки, табы (глоб. класс `.filter-tab`), бейджи, промпт, hero,
грид-layout, gap, sticky-сайдбар. **Классы:** переиспользовать DS-классы где есть (сверять
`styleNames`), свои — где нет.

### Фаза 2 — контент (родные блоки)
18 карточек + 6 секций с `data-filter-tags`/`data-title`/id: первую карточку — билдером,
остальные — **Cmd+D в Designer + `set_text`** (нужны клики пользователя); `data-*` — через
`set_attributes` (`alt` не трогать); локапы — `type: "Image"` + `set_image_asset`
(asset id = 24-символьный хэш в имени файла на CDN). Секциям — модификатор-класс (цвет
баннера + `--wf-c`).

### Фаза 3 — custom `<style>` (эффекты + состояния + мобилка)
Вставить в Page → Inside `<head>` правила из списка «остаётся в custom» + мини-`:root{}`.

### Фаза 4 — JS + проверка
1. IIFE в Page → Before `</body>`. **FAB + sheet создавать через `createElement` и
   `document.body.appendChild(...)`** — чтобы `position: fixed` не зависел от
   трансформируемого предка Webflow (как `review/cmtx`). `--nav-height` и глушение
   `scroll-behavior: smooth` — как в dev-версии.
2. Блок со `<script>` **не рисуется на канвасе Designer** → проверять только в **Preview**
   (с кастом-кодом) и на staging/паблише. `debug/embed-harness.html` тут не применяется.
3. Прогон: десктоп (двухколоночный + sidebar), мобилка 375/320 (H2 → фильтр 2×2 → контент,
   чёрный бар, панель с жёлтой обводкой, тап-скролл, закрытие).

## MCP-засады (CLAUDE.md, актуальные)
- `gap` через `data_style_tool` не ставится → задавать **в панели вручную**.
- `!important` — только custom-кодом.
- кастомные `--свойства` `data_style_tool` не принимает → `--wf-c` только в `<style>`.
- `duplicate` в API нет → повторяющиеся карточки Cmd+D в Designer.
- `TextBlock` не принимает `set_text` → тексты только `Paragraph`/`Heading`.
- `.container` конфликтует с глобальным Webflow-контейнером → `.uc-container` или отдать
  контейнер Webflow.

## Синхронизация
`use-cases.html` (dev) остаётся источником правды по вёрстке/логике; при правках блока,
живущего и в dev, и в Webflow, менять оба в одном изменении (правило CLAUDE.md).
