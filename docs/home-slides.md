## Модель — как это устроено

### Единицы и высотный коридор

Сцена нарисована на холсте шириной 1232. Одна дизайн-единица — `--u = 1cqw / 12.32` от ширины холста; каждая координата в коде — это число из Figma × `--u`. Высоту диктует **только ширина**.

У каждого состояния два кадра в Figma: `h364` (эталон и пол) и `h550+scale` (потолок: декор ×1,5, интерфейс 1:1). Фрагмент несёт геометрию h364 (`--x/--y/--w/--h`) и дельты к h550 (`--dx/--dy/--dw/--dh`), которые применяются пропорционально тому, насколько холст вырос над полом: `--up = clamp(0, 100cqh − 364u, 186u)`. На коротком desktop-окне (до 800px по высоте) холст принудительно остаётся на одобренном кадре `h364`; третьего кадра (h300) нет намеренно.

Высота холста: `clamp(364u, 100dvh − нав − --head-cost − бар − нижний отступ, 550u)`. Нижний отступ `--slide-gap-bottom` скрипт считает из реально оставшегося места (2rem, где есть воздух, 0 на полу). Композиция центруется по рул-карточке (`--cx: 616.5`), а не по контейнеру.

### Карточка — два блока

Визуально карточка не одна: сверху блок с копирайтом и кнопками, снизу — блок со сценой, между ними `--slide-split`.

| Элемент | Что это |
|---|---|
| `.hs__card` (`#card`) | прозрачная обёртка. Держит `--t`, `--slide-bg` и `container-type: inline-size` — от **её** ширины считается `--u-w`, а через него все координаты сцены |
| `.hs__head` | верхний блок: `.hs__bars` внутри, `padding-block: var(--pad-card)` |
| `.hs__canvas` | нижний блок, он же холст сцены |

Фон, радиус, `overflow: hidden` и переход цвета — общее правило `.hs__head, .hs__canvas`. `overflow` несущий у обоих: колонки бара ездят по вертикали при смене слайда, сцена выходит за холст на каждом шаге.

**Цвет** живёт в `--slide-bg` на `#card`: скрипт пишет его один раз (`card.style.setProperty('--slide-bg', …)`), оба блока читают. Разъехаться не могут. Фолбэк в CSS — `var(--color-accent-blue)`, то есть цвет слайда 0, поэтому без JS первый кадр верный.

**Зазор** `--slide-split` = `--gap-main` (1rem). Фиксированный rem, как `--pad-card`, а не единица макета: это хром карточки, он не должен расти вместе с холстом. Корневой кегль на странице плавающий, поэтому «16px из макета» — это 17.6px на 1440 ровно так же, как «24px паддинга» это 26.4px.

**Бюджет высоты.** У холста два потребителя одного и того же расстояния — «всё, что над ним». В CSS это `--head-cost` = `--pad-card × 2 + --slide-split`, которое вычитает `clamp`. В скрипте `lockBarHeight()` **меряет** то же расстояние по DOM: `canvas.offsetTop`. У карточки нет своего паддинга, поэтому смещение холста внутри неё — ровно верхний блок плюс зазор.

Мерить, а не складывать заново, — осознанно. Во-первых, при правке паддинга верхнего блока скрипт подхватит новое значение сам. Во-вторых, скрипту нельзя парсить `--head-cost`: это `calc()`, и `parseFloat` вернул бы `NaN` (см. грабли ниже). Высота фиксированного хрома тоже меряется как нижняя граница видимого `.nav2`/`.nav2m`, а не вычисляется из `--nav-height`: так sticky-сцена учитывает и промо-плашку над навом, и не расходится с rem-кеглем host-страницы.

### Непрерывная сцена: STEPS и K

Один DOM на все слайды. `STEPS` — список шагов через все слайды; слайд — это диапазон шагов, на границе меняются только бар и цвет карточки. Сейчас 7 шагов:

| # | Слайд | Что происходит | Длина (экранов) |
|---|---|---|---|
| 0 | Rules | коллаж | 1 |
| 1 | Rules | разлёт, стопка рулов выходит | 1 |
| 2 | AI | стопка схлопывается в «Your automation rules»; цвет и бар переключаются при `slideAt: 0.22` | 1 |
| 3 | AI | геометрия стоит, играет история чата | 1.8 |
| 4 | AI | routine: чат уходит в сторону, Trigger / Routine / папка | 1 |
| 5 | MCP | креативы перегруппировываются, телефон приезжает | 1 |
| 6 | MCP | геометрия стоит, играет история телефона | 1.8 |

`K` — таблица ключей: на каждый фрагмент массив по шагам, пропущенные поля наследуются от предыдущего шага. Ключ `n` описывает **вход в шаг n** и играет в сегменте `n−1`. Поля:

| Поле | Смысл |
|---|---|
| `x, y, w, h, r, o` | координаты, размер, поворот (градусы), прозрачность — в единицах кадра h364 |
| `d: [dx, dy, dw, dh]` | дельты к h550 |
| `e: [a, b]`, `ease` | окно внутри сегмента (доля 0–1), в котором играет переход, и его кривая |
| `via: {x, y, r, delay, rate}` | двухколенный полёт через «кучу» (креативы из-под холста в стопку, затем веером) |
| `auto: {delay, dur}` | твин по собственным часам с момента входа в сегмент |
| `auto: {delay, rate}` | лерп по собственным часам: `rate` — доля пути за кадр при 60 fps |
| `arm` | доля сегмента, при которой таймированный кусок взводится (по умолчанию 0.02 для лерпа, 0.5 для `via`) |
| `after: 'story'` | ждать, пока откроется гейт (история чата рассказана) |
| `pop: {delay}` | класс `is-in` через `delay` мс после взвода: жёсткий 120-мс шаг из масштаба 0.92 |

CSS смешивает ровно два ключа (`--x`…`--x2` через `--t`); скрипт решает, какие два, и пишет их (`writePair`). Каждый кадр `render(p)` переводит прогресс в номер сегмента и локальную долю, считает `--t` для каждого фрагмента по его окну и кривой, ведёт лерпы, гейты и классы.

### Тягучесть и таймированные куски

Прогресс идёт через вязкий фолловер: `shownP += (target − shownP) × 0.10` за кадр. Таймированные вещи (лерпы, `via`, `auto`, `pop`, история чата, телефон) живут на своих часах: скролл их запускает и может только поторопить (`hurry` при локальной доле ≥ 0.9), но не удерживает.

**Граница шага никогда не телепортирует элемент** (правило после #36). Лерп живёт на фрагменте, пока не сойдётся (в пределах 0.3 единицы): в чужом сегменте он догоняет точку, которую диктует скролл, и только тогда отдаёт управление блендингу. Лерп стартует с последней нарисованной позиции (`f.cur`), а не из ключа шага. Вход в таймированный шаг с дальней стороны (скролл назад) считается уже сыгранным (`clockFor`). Дельты коридора едут вместе с элементом — иначе на высоких экранах рамка прыгала на 35 единиц. Если после всего этого на границе элемент всё же оказывается не там, где был, он скользит туда (`startLerp` c rate 0.12). `pop`-элементы за своим шагом просто включены — иначе при перезагрузке внизу трека они не появлялись.

### Появление первого состояния (шаг 0)

Коллаж не стоит готовым: он собирается по кускам, а конструктор рулов (карточка с «Duplicate») прилетает в центр последним — это пойнт слайда. Шаг 0 — начало сцены, у него нет входящего сегмента, поэтому ключ `pop` его вести не может: вход взводится один раз `IntersectionObserver`'ом на карточке (порог 0.25).

Порядок и тайминг — в объекте `INTRO` в скрипте блока:

| Поле | Значение | Смысл |
|---|---|---|
| `at` | 220 мс | тишина после того, как блок попал в кадр |
| `step` | 90 мс | пауза между кусками |
| `breath` | 100 мс | добор перед тем, как ляжет конструктор (на 350 он читался отдельным событием) |
| `order` | список | порядок появления; вложенный массив = куски, входящие вместе |

Порядок написан руками, а не выведен из z-index или расстояния до центра: и то, и другое ставит конструктор в середину последовательности. Сейчас это левый кластер → правый кластер → бар интеграций → четыре платформенных кружка → конструктор. Три рул-карточки (`rule-card-pause`, `rule-card-increase`, `rule-card`) — одна запись: они лежат стопкой на одном месте, видно только верхнюю, и если пускать их по очереди, сначала мелькнёт карточка снизу.

Итого куски приезжают через 90 мс, последний — через 190 мс после предыдущего.

Два канала реванла нарочно разной длины:

| Канал | Длина | Зачем |
|---|---|---|
| прозрачность (`--in`) | 120 мс, `steps(3, end)` | эталонный жёсткий шаг блока — кусок **приземляется**, а не проявляется |
| масштаб `0.85 → 1` | `--intro-settle` = 420 мс, `cubic-bezier(0.16, 0.8, 0.24, 1)` | на 120 мс скачок такого размера — щелчок, который не успеваешь прочитать; здесь кусок приезжает резко и **доседает** в размер |

0.85, а не 0.92, как у чипов слайда 03: там реванл одиночный, здесь дюжина подряд. Доседание длиннее паузы между кусками — в любой момент несколько ещё растут, и это то, что сшивает двенадцать отдельных появлений в одну сборку.

`--intro-settle` — единственное место, где живёт длина: её берёт CSS-транзишен, и её же скрипт читает обратно, чтобы понять, когда вход окончательно улёгся и можно снимать маркеры. Снять их посреди доседания — значит защёлкнуть последний кусок в полный размер. Отличие в том, что он идёт через гейт `--in`, а не переписывает `opacity`: `--in` умножается в ту же формулу, что и `--lit`, поэтому кусок, притушенный ключом, остаётся притушенным. Кастомное свойство анимируется только зарегистрированным — отсюда `@property --in` (как `--ring-angle`).

Разметку вход не трогает: и атрибут `data-intro`, и класс `.is-intro` вешает скрипт, а после проигрыша снимает подчистую. Поэтому страница без JS показывает готовый коллаж (та же причина, по которой шаг 0 продублирован инлайном), а дальше по треку от входа не остаётся следов — в частности, тень стопки на шаге 1 снова едет по собственному `transition: filter`.

Вход живёт на своих часах: скролл может его **поторопить**, но не удержать. Уход с первого состояния (`progress() > 0.02`) досрочно доигрывает оставшиеся куски — иначе они остались бы невидимыми уже на следующем шаге. При загрузке с середины трека и при `prefers-reduced-motion: reduce` вход не взводится вовсе: коллаж просто стоит, как и `pop`-элементы за своим шагом.

`window.__hsIntroReplay()` — проиграть заново без перезагрузки (подбирать тайминг иначе невозможно).

### Схлопывание рулов (шаг 2)

Рамка `rules-frame` — не картинка поверх, а **закрывающееся окно** с `overflow: hidden`: на первых шагах она больше холста и ничего не режет, к 276×275 обрезает три вложенные карточки ровно как в Figma. Вложенные карточки — `.hs__frag--nested` (без центрирующего члена, `max-width: none` — иначе глобальный `img { max-width: 100% }` сжимает их до ширины рамки). Заголовок «Your automation rules» (`is-closed`) и синяя заливка читают собственную ширину рамки из лерпа, а не скролл, — поэтому они не рассинхронятся с закрытием.

### История чата (слайд 02)

`STORY = [0, 600, 950, 1900, 2850, 3800]` мс — состояния: вопрос → ответ начался → скан правил → бизнес-контекст → Meta Ads Library → готово. Статусы: «Analyzed performance trends / Understood business context / Searched Meta Ads Library». Строка `Used:` — только после сканирования. Источники подсвечиваются градиентным кольцом (`.hs__frag--ring.is-lit`, conic-gradient, у рулов внутри клипа); сущности выезжают из-под холста по `--lit`. Гейт `GATES.story` открывается через 1,7 с после вызова библиотеки — чтобы при поторапливании она успела прилететь до того, как рамка уходит. Сегмент чата — `CHAT_SEG = 2`.

### Телефон (слайд 03)

Основа — скриншот приложения Claude (`phone.webp`, 581×1218), поверх него DOM: область сообщений (в потоке, `top 96u`, отступы 18u — в линию с полем ввода), строка ввода с кареткой (`.hs__ph-typed`, текст и каретка в одном прокручиваемом блоке), плашки-тапы по клавишам (`KEYMAP` из замеренных рядов клавиатуры: ряд q на y=5 в слое клавиатуры, шаг 22.17, ширина 18.4). Типографика от реального экрана: 242 единицы = 390pt, 16pt = 10u; вес 400 (dev-среда ставит 600 всем). `phPlay()`: набор 50 мс/символ (shift перед заглавной, «123» перед «?»), отправка через 220 мс, ответ по словам 60 мс. Клавиатура остаётся после отправки, как в приложении. Сегмент — `PHONE_SEG = 5`, старт при доле 0.6 сегмента 4.

### Верхний блок и пейджер

Три бара наложены абсолютом над обёрткой фиксированной высоты `--bar-h` внутри `.hs__head` (смена слайда не двигает холст). Смена — сдвиг по Y + прозрачность, колонки со стаггером 80 мс. Кнопки по верхней кромке, бейджи — чёрный на 20% (литерал, токена нет). Пейджер — вертикальные точки слева вверху, активная вытянута в капсулу, заполняется прогрессом своего слайда; точки кликабельны.

## Как править

- **Сдвинуть элемент / поменять тайминг** — только в `K`: найти фрагмент по `data-frag`, поправить ключ нужного шага. Шаг 0 продублирован инлайном в разметке (сцена корректна без JS) — при правке шага 0 менять оба места.
- **Поменять появление коллажа** — только в `INTRO` (порядок и три числа) в скрипте блока; после правки `window.__hsIntroReplay()` в консоли, перезагрузка не нужна. Сам реванл — в CSS-блоке «First state: the collage assembles».
- **Добавить шаг** — строка в `STEPS` + ключ у фрагментов, которые в нём что-то делают; остальные наследуют. `len` — длина в экранах (по умолчанию 1).
- **Заменить ассет** — положить файл, поправить `src` и `w` (ширину слоя из Figma; высота у картинок auto). Экспорты из Figma обрезаются по контуру — сверять размер экспорта с размером слоя (см. `figma-mcp.md`). Ротированные слои: координаты брать из design context, метаданные врут.
- **Копирайт** — в барах (`<header class="hs__bar">`), в чате (`Q`, `A1`, `A2`), в телефоне (`PHQ`, `PHA`).
- **Ритм** — эталон: жёсткий шаг 120 мс, «вдох» 350 мс (референс ребрендинга Tinder). Предпочитать движение из реального источника (выезд из-под холста, скольжение) прозрачности.

## Как проверять

Ручной чек-лист перед коммитом:
1. Быстрый скролл через каждую границу шага — ничего не прыгает. Обязательно на **высоком окне** (≥ 1000 по высоте): на низком окне холст стоит на полу, дельты нулевые и класс ошибок не виден.
2. Скролл назад через все шаги и снова вперёд.
3. Перезагрузка страницы, стоя внизу трека — слайд 03 полностью собран, вход первого состояния не взводится (коллаж целиком на месте, если проскроллить наверх).
4. Вход коллажа: открыть сверху — куски собираются по одному, конструктор последним; проскроллить вниз в первую же секунду — оставшиеся куски доигрывают, а не остаются невидимыми.
5. Зазор между блоками одинаковый на всех высотах и на всех трёх слайдах, цвет блоков совпадает.
6. Три высоты: пол (364), середина, потолок (550) — панель геометрии внизу страницы умеет форсировать высоту холста (`--canvas-force`) и крутить длину шага.
7. Короткий desktop (например, 1066×650 CSS px): сцена равна ровно 364 дизайн-единицам, верх карточки остаётся ниже фиксированного хрома.

Автопробы делались Playwright-скриптами (Python: `pip install playwright pillow && playwright install chromium`). Принцип: в страницу подмешивается rAF-логгер, который каждый кадр пишет `window.__hs` (шаг, локальная доля) и `getBoundingClientRect()` ключевых фрагментов; скролл — `page.mouse.wheel` шагами с паузами; разрыв — кадр, в котором элемент сдвинулся больше чем на 12 px и втрое сильнее соседних кадров. Скрипты в репо не клались; воспроизвести по описанию — полчаса.

## Живая вставка в Webflow — что правилось по ревью (17.09.2026)

Блок стоит на `birch-testing.webflow.io` сразу после Trusted by. Внешнее ревью (Codex, 9 разрешений от 1920×1080 до 320×568) нашло набор проблем; ниже — что именно изменено в блоке и почему. Общий принцип всех правок один: **окружение меряется, а не выводится из токена** — у живой страницы фиксированный хром, гуттер контейнера и корневой кегль не совпадают с тем, что записано в переменных.

- **Высота хрома — `--hs-chrome-h`, посчитанная по DOM.** Скрипт берёт `getBoundingClientRect().bottom` у всех видимых `position: fixed` элементов `.nav2, .nav2m, [data-hs-chrome]` и пишет максимум в `--hs-chrome-h`; `--nav-height` остаётся фолбэком. Причина: при включённом баннере вебинара фиксированная шапка на 1280 была 157px, а блок резервировал 93.6px (`6.5em` от корневого кегля) — карточка уезжала под шапку. Своя шапка на чужой странице — добавить ей `data-hs-chrome`, ничего в блоке менять не нужно.
- **Гуттер хоста — `--hse-host-gutter`, тоже замер.** В Webflow блок лежит во **вложенных** контейнерах, и внутренний повторяет паддинг внешнего: на 320 карточка выходила уже соседних секций. Скрипт отменяет паддинг внутреннего контейнера **только если выше есть ещё один** — одиночный контейнер это собственные поля страницы, их трогать нельзя. Поэтому если контейнер из Designer убрать, правка сама отключится. Брать значение из токена `--_responsive---font-size--padding--horizontal` нельзя: на живой странице он `1.5rem`, а реальный паддинг 21.76px — токен не равен паддингу.
- **Короткое окно (1440×650).** Сцена остаётся 364 единицы (364 — это и есть `--scene-min`, ниже она не сжимается), поэтому место отдаёт **чром самой карточки**: до 800 по высоте `padding-block` головы 0.75rem и `--slide-split` 0.5rem, ниже 700 — 0.5rem и 0.375rem. На 1440×650 карточка теперь целиком в экране (верх под шапкой, низ на 4px выше сгиба); до правки вылезала на 45px.
- **Обрыв на 992.** Раскладки остались (992 — брейкпоинт Webflow, и нав переключается там же), но при пересечении границы переносится **слайд, а не смещение**: `rememberPlace()` на скролле, `restorePlace()` на resize. Иначе поворот планшета уносил читателя на тысячи пикселей — трек 5837px против 1969px у потока.
- **Картинки — `data-hs-src`, гидратируется только видимая раскладка.** Обе раскладки лежат в DOM одновременно, и `display: none` от загрузки не спасает: у скрытого элемента нет бокса, поэтому `loading="lazy"` его не откладывает — телефон качал все 55 картинок, включая 29 десктопных. Теперь в разметке нет `src` вообще, скрипт проставляет его только своей раскладке (на старте и при смене раскладки): 26 картинок на мобилке, 55 на десктопе. У каждого `<img>` есть `width`/`height`, поэтому ничего не прыгает.
- **`prefers-reduced-motion` — статический поток на всех ширинах.** Условие мобильного блока теперь `@media (max-width: 991px), (prefers-reduced-motion: reduce)`. Приглушить scroll-driven сцену недостаточно — она всё равно едет со скроллом; готовая статическая раскладка показывает каждую сцену целиком, что и требуется от альтернативы.
- **Точки пейджера — цель 44px оверлеем (`::after`), а не размером кнопки.** Колонка пейджера высотой всего с верхний бар (≈121px), три цели по 44px в неё не помещаются без нахлёста, а сам бокс должен оставаться маленьким, чтобы активная точка растягивалась в капсулу. Поэтому соседние цели перекрываются на несколько пикселей в зазоре — выигрывает нижняя (порядок в DOM), это детерминировано.
- **Прочее:** жёлтая CTA перестала быть белой на жёлтом (сброс `a { color: inherit }` теперь `a:not(.hse-btn)`), копия на планшете складывается ниже 820 (на 768 три колонки давили абзац в лесенку), мобильные кнопки ≥48px и ниже 360 в столбик, `:focus-visible` на CTA и коллажах, неактивные бары получают `inert` + `aria-hidden`.
- **Не делалось:** scroll-snap на мобильных коллажах. Коллаж — непрерывная панорама без естественных точек привязки; кадрирование решено стартовой позицией (`data-hsm-start`) и чипом «Swipe», а навязанный снап дерётся с драгом. Если понадобится — обсудить точки отдельно.

### Посадка карточки на странице (18.09.2026, по правкам на живой)

- **Карточка приколота на 20px ниже шапки, а не центрирована.** `--hs-head-gap: 1.25rem` (20px на базовом кегле 16px, дальше тянется вместе с флюидным корнем сайта) вычитается из `top` и высоты sticky и из клампа высоты холста. `align-items` у sticky — `flex-start`: **зазор под шапкой это фиксированная точка композиции**, и если окно не вмещает даже минимальную карточку, за экран уходит низ, а не верх. Проверено на 1440×650 (низ обрезан на 50px) и 1440×520 (на 180px) — верх обоих случаев стоит на месте.
- **Скрипт мерит от линии прикола, а не от шапки.** `pinOffsetPx() = chromeHeightPx() + headGapPx()` — по ней считаются прогресс трека, бюджет нижнего зазора и прыжки пейджера. `--hs-head-gap` читается как простой rem-токен: `calc()` там нельзя, незарегистрированное кастомное свойство скрипту его не разрешит (см. грабли ниже).
- **Нижний отступ блока — `--hs-block-gap: 1rem`, ритм бенто-сетки страницы.** У соседних блоков `margin-bottom: 1rem`, у секции с треком — ноль, поэтому следующий блок начинался вплотную к последнему слайду. Задаётся **margin'ом, а не padding'ом**: padding расширил бы containing block sticky-элемента, и последний слайд висел бы приколотым лишний экран.
- **У карточки нет своего `max-width`.** Был `1280px` в прелюдии embed'а — на 1900 карточка оказывалась на 99px уже соседних блоков с каждой стороны, а кегль внутри продолжал расти вместе с флюидным корнем: колонка бара переставала вмещать две кнопки, и «More about Rules» вылезала на 54px и срезалась `overflow: hidden` у головы. Ширину теперь диктует хост. Сцена это переживает, потому что её координаты — дизайн-единицы от ширины самой карточки (`--u-w`).

## Известные грабли (уже собранные)

- Метаданные Figma для ротированных/масочных слоёв дают bbox на 200+ единиц мимо; папка — bbox на 25 ниже, экспорт обрезан, угла в метаданных нет (11.93° взято от дизайнера). Правила записаны в `figma-mcp.md`.
- `.section` с паддингом 5rem на треке отклеивает sticky раньше времени — на `.hs` `padding-block: 0`.
- `--t`, объявленный на `.hs__frag`, перекрывает унаследованное значение — сейчас `--t` пишется каждому фрагменту отдельно.
- Атрибут `hidden` проигрывает `display` компонента — прятать инлайновым `display: none`.
- `--u` внутри `.chat-card-wrap` считается от контейнера чата, не холста — шрифт чата задан как `4.8cqi`.
- Просроченный `transition: box-shadow` на кольце перекрывал transition сдвига у сущностей («библиотека появилась из ниоткуда»).
- Замеры в скрытой панели браузера нестабильны — для проверок использовать Playwright. Отдельно: в скрытой вкладке не идёт `requestAnimationFrame`, поэтому `render()` не вызывается и `window.__hs` остаётся `undefined`. Это не поломка блока — сначала проверить `document.visibilityState`.
- **`parseFloat` кастомного свойства с `calc()` даёт `NaN`, и этот `NaN` убивает сцену целиком.** Вычисленное значение незарегистрированного кастомного свойства — это токен как написан (`calc(1.5rem * 2 + 1rem)`), а не разрешённая длина. Цепочка: `parseFloat` → `NaN` → скрипт пишет `--slide-gap-bottom: "NaNrem"` (валидное значение кастомного свойства, поэтому принимается молча) → `calc()` высоты холста, куда оно подставляется, становится invalid at computed-value time → `height: auto` → а под `container-type: size` это **ноль**. Сцена исчезает, остаётся только верхний блок. Причём CSS сам по себе выжил бы: вложенный `calc()` подставляется законно, ломает именно `parseFloat`. Отсюда два правила: скрипт не парсит производные токены (мерит по DOM), и в `--slide-gap-bottom` не уходит нефинитное число (`isFinite`-гард). Регистрировать свойство через `@property`, чтобы оно резолвилось для скрипта, — рабочий, но хрупкий путь: достаточно, чтобы сборка выкинула `@property` (а блоку ещё ехать в Webflow-embed), и падение будет тихим и полным.
